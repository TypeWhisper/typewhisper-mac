# 代码标准

* 禁止用脚本或命令批量改写源代码文本，包括 heredoc、python 脚本、sed、perl 等；所有源代码修改都通过编辑工具逐处完成。格式化工具、包管理器、官方脚手架和代码生成器、数据库迁移工具可以正常使用。
* 需要第三方库时直接引入成熟的库，不追求最小化依赖，禁止自己重新实现或用其他方式绕开依赖。
* 实现和测试中禁止使用 mock、伪造的数据或结果，以及任何只为让测试通过的变通手段。单元测试可以用替身代替系统服务和网络连接（例如开机启动服务、下载连接），避免测试修改本机设置或真实联网；替身只能写在测试代码里，测试的输入和期望结果必须是真实数据。
* 每个功能都要实施、运行、测试、修复，直到正确运行，禁止实现后让我去测试。遇到必须由我提供的条件（密钥、账号、付费服务、只能在我的设备上完成的操作）时，停下来说明缺少什么。
* 我修改过的内容以我的版本为准，禁止恢复。
* Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.
